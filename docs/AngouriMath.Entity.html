  • Betaf

    Summary

    The beta function B(a, b) = Γ(a) Γ(b)/Γ(a + b) (DLMF 5.12.1), written beta(a, b). It has no

  • Binomialf

    Summary

    A node of the binomial coefficient binomial(n, k), "n choose k".

    Remarks

    A node rather than n!/(k! (n - k)!): that quotient is correct and useless as a
    spelling -- it loses the integrality, it is undefined for a negative n where
    the falling factorial n (n - 1) ... (n - k + 1)/k! is not, and no rule can
    recognise Pascal's identity or Vandermonde's in a ratio of three factorials. The
    falling factorial is the definition for a whole k, whatever n is; a
    whole k below zero gives 0; and for a k that is not whole the
    value is Γ(n + 1)/(Γ(k + 1) Γ(n - k + 1)), which has no value where n is a negative whole number. What cannot be settled is left as this node.
    https://github.com/asc-community/AngouriMath/issues/1409
    https://github.com/asc-community/AngouriMath/issues/809

  • Conjugatef

    Summary

    The complex conjugate conjugate(z), also written conj(z): a - b i for
    z = a + b i.

    Remarks

    An involution that fixes the real numbers and sends i to -i, and a field
    automorphism, so it is carried through sums, differences, products, quotients and whole
    powers. It is not carried through a root or a logarithm: their branch cuts lie on the

  • Constant

    Summary

    A mathematical constant: a number whose spelling happens to be a legal identifier.

    Remarks

    It is a Variable by inheritance, so everything that reads a leaf by name
    keeps working, and a distinct type by record identity, which is the whole point: a
    binder that declares pi and the constant pi are no longer one object, so
    evaluation can tell them apart without being told where it is.
    #984     A binder binds occurrences, not values, and that is the whole of the second
    distinction here. Every constant a writer types is the one object in
    NamedConstants, because the parser and pi hand that
    object back; the base of ln and of exp is
    EulerIntrinsic, a separate object, because it is Euler's number standing
    in an operator's own definition and not a reference to the name e. A binder
    replaces the occurrences it was handed — compared by reference — so
    sum(ln(x), e, 1, 2) is 2 * ln(x) while sum(log(e, x), e, 1, 2),
    where the writer did name e, is log(1, x) + log(2, x).
     The two are equal, and deliberately so: they are the same number, they print
    alike, and any rule that matches one matches the other, so nothing about canonical form,
    equality or substitution changes. Only the identity of the occurrence differs, and only
    while a binder is deciding what it binds — which is at construction, before anything
    evaluates.

  • NodeStack

    Summary

  • PartialDerivativef

    Summary

    A partial derivative, ∂L/∂q: the derivative of Expression in the slot Var, with everything else held fixed.

    Remarks

    Where Derivativef is the total derivative, which follows everything that
    moves when its variable does, this holds fixed whatever is not its slot. The two agree
    over a variable. Over an unknown function applied, q = f(x), or a derivative of
    one, f'(x), they do not: f' and x are other slots, as in the
    Euler–Lagrange equation, so the partial derivative of f^2 + f'^2 in f is
    2f, and the total derivative is 2f + 2f'' where f' ≠ 0.
     A slot is a variable, an unknown function applied, or a derivative of one in a
    variable. Over any other expression the node is left as written: x^2 and
    x * x are one value, and the slot x^2 occurs in only one of them.
    It does not bind its slot: it is a function of it, as a derivative is.#230

  • PrimeFactorizationf

    Summary

    The prime factorisation of a positive integer, factorization(n): the finitely
    supported map from each prime p to its exponent v_p(n) in n, which
    is mathlib's Nat.factorization. factorization(360) is
    2 ↦ 3, 3 ↦ 2, 5 ↦ 1, and factorization(1) the empty map.

    Remarks

    By the fundamental theorem of arithmetic a positive integer is its exponent vector, and
    multiplying integers adds the vectors; so the factorisation is that map, with
    primefactors(n) its support and valuation(n, p) its value at p, and
    product(p ^ valuation(n, p), p in primefactors(n)) = n.
     A node of its own, and not the product 2^3 * 3^2 * 5, which evaluates to the
    number it was meant to explain; nor a number, so it does not equal n. Defined on
    the positive integers, and NaN at any other number, as primenu is: 0 has no
    factorisation, and a negative integer is -1 times one, which the map cannot write.
    Left as written for an expression, and for an integer with a factor neither proven prime
    nor split, whose Factors is then null.
    https://github.com/asc-community/AngouriMath/issues/2449

  • Quantifier

    Summary

  • RisingFactorialf

    Summary

    The rising factorial risingfactorial(x, n), x to the n rising: x (x + 1) ... (x + n - 1) for a whole n >= 0, in the notation x^{\overline{n}} of Graham, Knuth and Patashnik's Concrete Mathematics.

    Remarks

    For a negative whole n it is 1 / ((x - 1) (x - 2) ... (x + n)), and for any other n it is Γ(x + n) / Γ(x), as Mathematica's Pochhammer is. The name pochhammer is refused, since the Pochhammer symbol is the falling factorial to some authors.
    https://github.com/asc-community/AngouriMath/issues/2182

  • Roundf

    Summary

    A node of round: the nearest integer, with a tie going to the even one.

    Remarks

    Half to even, which is what Python, SymPy, Mathematica and IEEE 754 all do — and

    of it. So round(1/2) is 0 and round(3/2) is 2, and it
    is notfloor(x + 1/2), which differs at every tie.

  • Summationf

    Summary

    A summation over a bound variable: sum(f, i, from, to) is
    f(from) + … + f(to).

    Remarks

    A CalculusOperator rather than a Sumf of many terms,
    because the bounds may be symbolic — sum(i, i, 1, n) has no finite expansion
    and is still a well-formed expression. Where they are concrete integers it expands,
    which is what makes the common case useful without the general case being wrong.
     The index is bound: it is the summation index, not a free variable of
    the expression, so substituting it from outside must not reach inside. That is the
    property ConditionalSet already has and the one
    #878 was about
    getting wrong.
    #248

  • SumOverSetf

    Summary

    A sum over a set: sum(f(x), x in S) is the sum of f(x) over the members
    x of S, each counted once. A binder, like Summationf, whose
    range is a set rather than two bounds, and so has no index and no order: the sum over
    the roots of a polynomial is sum(f(w), w in { w : p(w) = 0 }), which needs no
    first root.
    https://github.com/asc-community/AngouriMath/issues/1285
