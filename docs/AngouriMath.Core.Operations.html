AngouriMath.Core.Operations

← Back to list of namespaces

Classes within the AngouriMath.Core.Operations namespace

  • Catalogue

    Summary

    Every operation the library offers by name, which the terminal and the MCP server take
    theirs from.

    Remarks

    The names are the ones
    #1019 item 16
    proposes for amcli's commands in v3: the library's own verbs, so simplify rather than simp and differentiate rather than diff.
     An operation is in this list when a surface offers it, or could offer it with nothing
    but text in and text out. The building blocks Transformation also names,
    such as RationalCanonicalization or
    EqualitySaturation(AngouriMath.Core.Budgets.WorkBudget,AngouriMath.Core.CostModel), are not: a caller composes them, and
    none answers a question by itself. A test lists every factory of
    Transformation as one or the other, so that a new one fails the build
    until it is placed.
     https://github.com/asc-community/AngouriMath/issues/1684

  • Operation

    Summary

    One thing the library does, under the name a caller asks for it by. The terminal's
    commands and the MCP server's tools are each made of these, and Catalogue lists every one.

    Remarks

    Internal until v3, while the shape of an entry may still move. The stable surface is the
    methods on Entity and MathS, and an entry answers exactly
    what the method it names answers.
    https://github.com/asc-community/AngouriMath/issues/1684

  • Parameter

    Summary

    One argument an Operation takes besides its input.

    Parameter "Name"

    Its name, such as variable.

    Parameter "Description"

    What it is, in one sentence.

  • Query`1

    Summary

    An operation whose answer is not an expression standing for the input: a set of
    solutions, a number, text, a table.

    Type parameter "TAsk"

    Its signature: the input, then each of Parameters, and the
    answer back.

  • TransformationOperation`1

    Summary

    An operation whose answer is an expression that stands in a stated relation to its
    input: one of the Transformations, applied as the method on
    Entity applies it.

    Type parameter "TApply"

    Its signature: the input expression, then each of Parameters,
    and an expression back.
